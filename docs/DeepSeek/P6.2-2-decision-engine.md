## 一、目标（ChatGPT P6.2 审查锁定）

1. **DecisionEngine = gate**：输出 Allow/Skip/Degrade，不直接返回 Policy
2. **Decision 带原因**（audit 可解释：Measure → Adjust 闭环）
3. **DecisionEngine 不读 proc**（context 由调用方组装，eBPF 源可平替）
4. **多时间尺度 Context**：fast(1-5s) + slow(30-60s)
5. 替换 relock 裸 `oom_adj > 500` 阈值

---

## 二、实现内容

### decision.rs — 正式决策接口

```rust
enum Reason { ForegroundInteractive, Background, Frozen,
              ThermalPressure, MemoryPressure, AuditFailureRate, ForceAffinity }

enum DegradeLevel { SkipOnce, Observe, Relax }

enum Decision { Allow { reason }, Skip { reason },
                Degrade { level, reason } }

struct DecisionContext {
    intent: TaskIntent,        // per-pid
    pressure: PressureLevel,   // fast: 内存压力
    thermal_pressure: f64,     // fast: 冷却设备使用率 0-1
    foreground: bool,          // fast: 前台（engine 用 intent==Interactive 近似）
    audit_failure_rate: f64,   // slow: 审计失败率 0-1
}

DecisionEngine::decide_ctx(&ctx) -> Decision   // 零 I/O 纯函数
```

决策语义（relock 场景）：
- Frozen / Background → `Skip`（永不干预 / 省电交还调度器）
- 热压力 > 0.8 → `Degrade(Relax)`（避免多余唤醒/迁移）
- 审计失败率 > 50% → `Degrade(Observe)`（大概率再失败，先观察）
- 内存压力 Critical → `Degrade(Relax)`（压力感知降级）
- 否则 → `Allow`

### audit.rs

- `AuditSummary::failure_rate() -> f64`（slow 信号，失败 = total − success）

### engine.rs

- `RelockContext { pressure, thermal_pressure, audit_failure_rate }`
- `relock_all(..., rctx, decision)`：每进程组装 DecisionContext → decide_ctx →
  Allow 才 apply；Skip/Degrade 跳过本轮重应用
- 旧 oom_adj 阈值删除

### daemon/main.rs

- 保存最近 SystemContext 快照（`last_sys`，fast 信号）
- `build_relock_ctx` 闭包：pressure/thermal（fast）+ audit failure_rate（slow）
- 两处 relock 调用（配置变更 rescan + 周期）接入决策门控
- **daemon 的 `decision_engine` 实例生效**：`migrate-action "force"` 配置 →
  force_affinity_enabled → 所有决策 Allow（强制模式）

## 三、测试（53 → 60，+7）

| 测试 | 覆盖 |
|---|---|
| `ctx_frozen_and_background_skip` | Frozen/Background → Skip |
| `ctx_thermal_pressure_degrades` | 热 >0.8 → Degrade(Relax) |
| `ctx_audit_failure_rate_observes` | 失败率 >50% → Degrade(Observe) |
| `ctx_memory_pressure_critical_degrades` | Critical → Degrade(Relax) |
| `ctx_normal_allows` | Interactive/BLS 正常 → Allow |
| `ctx_force_overrides` | force 模式无视一切 → Allow |
| `ctx_bls_not_degrades_on_moderate` | Moderate 不降级（与 H1 语义一致） |

冒烟：relock 周期经决策门控正常（sleep → oom_adj 0 → Interactive → Allow → 重应用）。

## 四、待同事复核

1. **foreground 近似**：relock 里 `foreground = intent == Interactive`（oom_adj ≤ 200
   或负值视为前台）。pid→uid 精确映射留 DESIGN-1（需要 /proc 遍历 + uid 匹配）。
   这个近似是否可接受？
2. **Degrade 的记录点**：Skip/Degrade 目前直接 continue，reason 未写入 audit。
   建议 P6.2-3 加 `audit::record(DecisionEntry)`（relock 级审计，与 apply 级分离）。
3. **decide_ctx 阈值**：热 0.8 / 失败率 0.5 / Critical 降级——是否该配置化？
   （当前硬编码，ChatGPT P6.2 未要求配置化，先保持）
4. **force 语义**：`migrate-action "force"` 现在绕过一切门控（含 Frozen）。
   强制模式是否也应跳过 Frozen？（当前语义：force = 用户显式要求，全放行）
