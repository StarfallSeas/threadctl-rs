## 一、C1 IPC CLI（IMPL-2，~150 行 + 5 单测）

### 架构（三审采纳：独立线程 + mpsc，与 hot-reload 一致）

```text
daemon 侧：UnixListener 监听线程（socket 0750 root-only）
  accept → 读一行 → parse_request（白名单）→ mpsc 发主循环
  主循环 try_recv → handle_ipc（持有 tracker 执行）→ 响应回写 socket
CLI 侧：threadctl status|dump <pid>|reload|apply <pid>
  socket 路径：TC_SOCKET env 或默认 ./run/threadctl.sock
```

### 命令

| 命令 | 输出 |
|---|---|
| `status` | 版本/配置版本/跟踪进程与线程数（前 20）/audit 60s 摘要/relock 统计 |
| `dump <pid>` | applied_tids 数/allowed_mask/cpuset 归属/alive——排查"线程是否生效"直接看 |
| `reload` | 触发 store.reload + 通知事件源 + retain + 全量重应用（替代改文件等待热加载） |
| `apply <pid>` | 全量重应用（诊断用） |

### 安全

- socket 0750 root-only；命令**白名单**解析（未知命令回退 status，不执行任意命令——`rm -rf /` 测试被拦）
- 5 个单测：status/dump/reload/apply 解析 + 未知命令回退
