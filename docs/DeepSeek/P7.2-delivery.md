## 一、B1 自适应 relock（规划书 B1，~200 行含单测）

### 设计（防震荡三约束，三审一致）

```text
信号：sample_coverage（每 5s 抽样全部跟踪进程 /proc/<pid>/cpuset 归属，
      被移出我们 cpuset 的比例 0.0~1.0）
逻辑：
  观察窗口 ≥30s（6 采样）满才调整
  窗口内覆盖 ≥50% → 缩短一级（60→10→3s，rank 下限）
  窗口内零覆盖连续 60s → 延长一级（10→60→300s，rank 上限）
  单次覆盖/部分覆盖 → 不调整，重置稳定累计
```

### 实现要点

- `AdaptiveRelock`：rank 状态机 + `VecDeque<bool>` 滑动窗口 + `stable_secs`
- `from_initial(secs)`：尊重用户 `lock-interval` 配置起步（映射最近档位）
- 档位表 `INTERVALS_SECS = [3, 10, 60, 300]`——缩短/延长都邻接（60 缩短到 10 而非直接 3，符合规划书路径）
- 8 个单测：默认 60 / 窗口未满不调整 / 持续覆盖缩到 3s 下限 / 单次覆盖不调整 / 稳定延长到 300s 上限 / ratio API

## 二、D3 即时 relock + RelockGuard（规划书 D3 + ARCH-3）

### RelockGuard（共享冷却闸门）

```rust
struct RelockGuard { last_at: Instant, cooldown_ms: u64 }
try_lock(): cooldown 内 false，否则记录并 true
```

- **所有 relock 入口统一检查**（ARCH-3）：周期 relock（B1）与即时 relock（D3）共享
- D3 冷却 1s（防风暴）；3s 最短周期下 D3 天然冗余（周期已够快，guard 挡住）
- 3 个单测：首次放行 / 冷却拒绝+过期放行 / cooldown=0 恒放行

### D3 覆盖检测 + 即时 relock

```text
main 循环每 5s：
  ratio = sample_coverage(tracker, BASE_CPUSET)
  adaptive.observe_ratio(ratio)          ← B1 喂窗口
  if ratio > 0 && guard.try_lock():
      relock_all()                        ← 不等周期即时对抗
      last_lock = now                     ← 周期检查跳过（防叠加）
```

## 三、TRACKED_TGID_MAP（BUG-M3 根本修复，Claude P7.1 Q3 确认方案）

### 内核（threadctl-ebpf）

```rust
#[map] static TRACKED_TGID_MAP: HashMap<i32, u32> = HashMap::with_max_entries(1024, 0);
// EXIT handler：查表未命中 → return 0（未跟踪进程 EXIT 内核态丢弃）
```

### 用户态（EbpfSource）

- **插入**：fork/thread_clone 确认（cmdline 就绪 + is_interested）后
- **移除**：进程退出事件（tid==pid）到达时
- **同步**：30s 周期与 tracker 对齐（防 cleanup_dead 路径残留）

### 效果

- ringbuf 压力从"全量 EXIT"降到"跟踪集"（EXIT 用户态锁 tracker hotspot 随之消除——到达的都是跟踪进程）
- EXIT 事件到达的仍是跟踪集内（IMPL-4 线程清理不受影响）

## 四、--debug 工程级日志（排查指令）

| 入口 | 说明 |
|---|---|
| `--debug` | CLI flag |
| `TC_DEBUG=1` | 环境变量（脚本/su 场景） |

格式：`[debug][module] message`——按模块 grep 分域排查：

| 模块 | 内容 |
|---|---|
| `[ebpf]` | raw 事件（type/pid/tid/comm）、pending 入队/丢弃、Tgid 分流、白名单键、initial_scan、tracked 管理 |
| `[engine]` | scan 明细（pid/pkg/tids/has_thread_rules）、每线程名+规则命中（cpus/dir）、pkg 不感兴趣丢弃 |
| 启动 | debug 开关确认 |

实现：`debug.rs` 单 AtomicBool + `debug_log!` 宏（模块参数）——**运行时零开销**（单次 load）。

**排查价值**（游戏线程不生效场景）：`grep "\[engine\]" log | grep "tid="` 直接显示每个实际线程名与规则命中——GameThread/UnityMain 拼写不符一眼定位。
