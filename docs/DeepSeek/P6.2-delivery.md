## 二、当前状态

### 已冻结

- **P6.1 包匹配器**（P6.1-pkg-matcher.md）：RuleMatch{index,source}、nginx
  specificity、继承语义（exact override wildcard + 低优先级填充）、实例级缓存。
  ChatGPT 三轮审查通过，Claude P6.1 审查 14 项全部闭环。**正式冻结，不再改动。**

### 本轮交付（P6.2-1 Policy Merge Engine，已落地）

1. **merge.rs 独立**（新文件）：`merge_rules()` + `fill_missing()` +
   `MergeStrategy` 枚举。ruleset.rs 瘦身为纯匹配（matcher 找来源，merge 定策略）。

2. **MERGE_TABLE 数据驱动策略表**（单一事实源）：

   | 字段 | 策略 | 语义 |
   |---|---|---|
   | cpus | BitOr | 组内并集（高优先级组胜出） |
   | sched | FirstWins | 首个有值者生效 |
   | nice | FirstWins | 首个有值者生效 |
   | uclamp_min | Max | 保底累积（任何来源不能降低已有保底） |
   | uclamp_max | Min | 上限累积（任何来源不能突破已有上限） |

3. **RuleSource::priority() 显式优先级表**：Global=0 → Profile=50 → Group=60
   → PackageWildcard=80 → PackageExact=90 → ThreadType=95 → ThreadExact=100。
   不依赖 enum Ord 声明顺序（插入新变体不会静默改变优先级）。

4. **README Architecture Invariants**：明确 threadctl-rs 不会（LMKD/freeze/
   kill/migrate/取代调度器）与提供（affinity/sched/uclamp 约束/提示/可观测性）。

### 测试与质量

- **51 单测全绿**（+3 本轮：merge 表一致性、约束合并、匹配-合并解耦）
- **零警告**（cargo check --workspace）

## 三、请两位同事重点复核的问题

### 给 ChatGPT 5.5（架构层）

1. **MERGE_TABLE 是否完整表达 P6.2 采纳的语义**？当前字段只有 cpus/sched/
   nice/uclamp_min/uclamp_max 五项。若 P6.2-3 Backend 层加入新执行维度
   （如 cgroup v2 的 cpu.weight），策略表是否需要扩展机制？
2. **priority() 数值分布**：50/60/80/90/95/100 的间隔是否给未来来源
   （如 ThreadWildcard、AppGroup）留了合理插入空间？
3. **merge_rules 的 None 语义**：所有字段空 → None → resolve 返回 None →
   线程保持系统默认。这与"白名单占位规则（仅 sched）"的交互是否自洽？
   （sched-only 规则：cpus 空但 sched 有值 → Some，仅应用调度属性 ✓）

### 给 Claude Opus（实现层）

4. **merge.rs 的分组 flush 逻辑**：`cur_source` 分组 + 组内 BitOr 累积，
   跨组覆盖。边界：同 source 的规则在编译时是否保证连续？（`collect_pkg_matches`
   先 exact 后 wildcard，同 source 连续 ✓；排序后再处理 ✓）
5. **Priority 表与继承语义的一致性**：fill_missing 只在"线程规则命中"分支
   调用；纯包级路径直接 merge_rules。两个分支的字段语义是否已覆盖全部组合？
6. **实例级缓存**：`cache: Mutex<HashMap<pkg, Vec<RuleMatch>>>` 在 resolve
   并发（多线程 apply）下锁竞争是否可接受？P6.2-5 计划的 Arc<[RuleMatch]>
   零拷贝改造是否必要现在做？

### 给两位共同（跨层）

7. **P6.2-2 DecisionEngine 接入的输入签名**（规划）：
   `evaluate(TaskIntent, SystemContext, ForegroundState, AuditSummary) -> Action{Allow,Skip,Degrade}`。
   审计 summary_windowed(60) 作为 Adjust 输入——60s 窗口对决策是否合理粒度？
8. **文档结构**已按"产出方"重组为 `docs/DeepSeek/`、`docs/ChatGPT/`、
   `docs/Claude/` 三目录，文件名人类可读。两位同事后续审查文档请按
