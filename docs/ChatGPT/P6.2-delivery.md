Q1. MERGE_TABLE 是否完整表达未来执行维度？

结论

当前完整，扩展机制合理。

但建议不要把未来字段直接加入现有 enum，而是保持开放。

当前：

enum MergeStrategy {
    Override,
    FillMissing,
    BitOr,
    FirstWins,
    Max,
    Min,
}

已经覆盖目前所有字段。

未来：

例如：

cpu.weight
io.weight
memory.high
latency_nice

不应该修改 matcher。

应该新增：

struct Policy {
    cpus: Option<CpuSet>,
    sched: Option<SchedPolicy>,
    nice: Option<i32>,
    uclamp_min: Option<u32>,
    uclamp_max: Option<u32>,

    // future
    cpu_weight: Option<u32>,
}

然后：

MERGE_TABLE

cpu_weight -> Max/Override/Min

即可。

建议

未来 P7 可以考虑：

trait MergeField {
    fn strategy() -> MergeStrategy;
}

但目前不要。

P6.2 保持表驱动即可。

 }
