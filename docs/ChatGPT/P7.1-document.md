1. AI 主导定位审查

当前项目定位：

> AI 主导的软件工程实验项目



这个定位可以保留，不建议隐藏 AI 痕迹。

原因：

项目卖点不是“某个人写了一个线程控制器”，而是：

AI 架构讨论能力

AI 代码生成能力

AI 自我审查能力

多模型协作能力

AI 工程闭环能力


因此文档中：

✅ 可以出现：

AI-assisted development
AI-generated implementation
AI architecture review
AI code audit
AI collaboration record

但避免：

完全无需人工
AI自动完成全部工程
100% AI创造

原因：

工程项目中仍然存在：

需求提出

方向选择

最终决策

真机验证


这些属于人类控制层。

推荐描述：

AI 主导开发，人类负责方向确认、最终决策与实机验证。

比：

AI 99%，人类1%

更加工程化。

---

推荐 README 开头

# threadctl-rs

An AI-driven Android/Linux thread policy controller.

threadctl-rs is an experimental task policy engine designed for
Android devices, focusing on thread affinity, scheduler policies,
uclamp control and system observability.

This project explores AI-assisted software engineering:
architecture design, implementation, review and documentation
are collaboratively produced by multiple AI models.

Human involvement:
- requirement definition
- architecture decisions
- final validation

中文：

threadctl-rs 是一个 AI 主导的软件工程实验项目。

项目探索多模型 AI 协作完成复杂 Linux/Android 系统软件开发流程：

- DeepSeek V4 Flash：主要实现与工程推进
- Claude Opus：代码与架构审查
- ChatGPT：文档、设计与工程规范审查

人类负责需求方向、最终裁决以及真实设备验证。
